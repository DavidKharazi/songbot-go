# Song Bot (Go)

Переписанная на Go версия телеграм-бота для поиска текстов и аккордов церковных песен.

## Что изменилось по сравнению с Python-версией

- **Язык:** весь бот переписан на Go, без сторонних библиотек — только стандартная
  библиотека (`net/http`, `archive/zip`, `encoding/xml`, `encoding/json`). Это значит,
  что для сборки не нужен `go mod tidy` и доступ в интернет — достаточно `go build`.
  - Telegram Bot API реализован напрямую поверх `net/http` (long polling, отправка
    сообщений, файлов, редактирование сообщений, инлайн-клавиатуры).
  - Чтение `.docx` реализовано вручную через распаковку zip и разбор `word/document.xml`.
  - Обращение к Gemini сделано как обычный REST-запрos к
    `generativelanguage.googleapis.com`.
- **Дизайн кнопок и эмодзи обновлён:**
  - Стартовое меню: `🗂️ Каталог по алфавиту`, `🎼 Все песни`.
  - Буквы алфавита: `🔤 А`, `🔤 Б`, ...
  - Список песен: `🎵 Название песни`.
  - Пагинация: `⬅️ Назад` / `➡️ Ещё`.
  - После открытия песни: `✝️ Библейский стих к песне`, `🗂️ Каталог по алфавиту`,
    `🎼 Все песни`.
- **Одна кнопка "Аккорды" убрана.** Теперь при выборе песни бот сразу присылает
  **два файла** — текст песни (`.docx`) и аккорды (`.pdf`), если они найдены, без
  необходимости нажимать отдельную кнопку.
- **callback_data по индексу, а не по названию.** У Telegram есть жёсткий лимит в 64
  байта на `callback_data`. В python-версии туда клался текст названия песни целиком,
  что могло ломаться на длинных русских названиях. В Go-версии кнопки песен используют
  числовой индекс в отсортированном списке (`song|17`), что полностью снимает эту
  проблему.

## Структура проекта

```
songbot/
├── main.go                     # точка входа, чтение .env, запуск бота
├── go.mod
├── songs/                      # .docx файлы с текстами песен (как и раньше)
├── chords/                     # .pdf файлы с аккордами (как и раньше)
└── internal/
    ├── telegram/                # минимальный клиент Telegram Bot API
    ├── docxread/                 # извлечение текста из .docx (zip + XML)
    ├── songs/                    # загрузка песен/аккордов, нечёткое сопоставление имён
    ├── gemini/                   # REST-клиент Google Gemini
    └── bot/                      # обработчики команд/кнопок, клавиатуры
```

## Запуск

1. Скопируйте `.env.example` в `.env` и заполните токены:

   ```
   BOT_TOKEN=...
   GOOGLE_API_KEY=...
   ```

2. Положите файлы песен в `songs/*.docx`, аккорды — в `chords/*.pdf` (имена файлов
   можно не подгонять один к одному — сопоставление по похожести имени работает
   так же, как в python-версии).

3. Соберите и запустите:

   ```bash
   go build -o songbot .
   ./songbot
   ```

   Или сразу запустить без сборки:

   ```bash
   go run .
   ```

Зависимостей нет — `go.sum` не требуется, `go mod tidy` можно не запускать.

## Известные ограничения (перенесены из python-версии как есть)

- Поиск через Gemini на каждый запрос отправляет в промпт тексты **всех** песен —
  при большой базе это может упереться в лимит контекста модели или бюджет токенов.
- Нечёткое сопоставление аккордов с песнями — эвристика (на основе расстояния
  Левенштейна), не гарантирует идеального результата на очень похожих названиях.
